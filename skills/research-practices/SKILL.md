# Research practices

Find out how this is done now, so the plan doesn't rest on stale memory.

1. Name the question in one line, including the stack and the constraint (for example,
   "personal project, low cost").
2. Search. Prefer official docs and recent write-ups; note the date of what you rely on.
3. For any package, provider or action version, look it up with the tool
   (`npm view`, `pip index versions`, `gh release list`), not from memory.
4. Report at most five findings: what the standard approach is, what changed recently,
   and what to avoid. Each has a source link. Say when sources disagree.

Change nothing.
